# Godser #471, fase 1: navne, sammenlægning og to niveauer — implementeringsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Én række pr. gård og pr. majorat på besiddelsessiden, med art (gård/grevskab/baroni/stamhus) og »hører under«, uden at et ejerforhold, et billede eller bogens formulering går tabt.

**Architecture:** Databasen får ordforrådet `estate_slags`, to nye relationsroller (`hører_under`, `sammenlagt_i`) med en vagt-trigger og fem `red_*`-funktioner, der flytter koblinger med UPDATE (så hændelser og evidens følger med, og fortryd virker gennem `log_change`). En sammenlagt række bliver liggende med en `sammenlagt_i`-relation til den overlevende; web og mobil skjuler den og sender gamle adresser videre. Data ændres i prod af et R-script, der kun udfører en plan-fil, projektejeren har godkendt i et HTML-ark (hash-bundet).

**Tech Stack:** PostgreSQL 17 (Supabase), plpgsql `SECURITY DEFINER`; TypeScript (`@daa/core`, web Vite/React + vitest, mobil Expo + jest); R (`ops$rpc`); Python til forslagsarket.

**Spec:** `docs/decisions.md` »BESLUTTET: godserne ryddes op i to niveauer — majorat og gård (#471, 2026-11-26)«. Fase 2 og 3 er uden for denne plan.

## Global Constraints

- Invariant 1: ingen påstand overskrives. Bogens fulde navneform sættes som `citation.citat_tekst` på hvert ejerforhold, hvis gods omdøbes, sammenlægges eller som kopieres — kun hvor `citat_tekst IS NULL` (i dag 0 af 750).
- Invariant 2: ingen nye tabeller. Nye behov er vocab-rækker og relationsroller.
- Invariant 9: `estate.slags` ∈ vocab-scheme `estate_slags` = `{gård, grevskab, baroni, stamhus}` eller NULL.
- Parentesen fjernes ikke fra et navn i fase 1 ud over den sammenlægning, projektejeren godkender; periode/art udledes først i fase 2.
- Rækker, som et slettet ejerforhold i `change_event` peger på, lægges aldrig sammen væk (16 godser; listen beregnes i Task 10).
- Ingen nye anon-grants. Nye funktioner er `red_*` (redaktion), dækket af den eksisterende red_*-vagt; de skal stå i allow-listen `db-rls.sql:755-770` og i `db-verify.sql:3125-3150`.
- Prod: DDL som navngiven blok (`-- BEGIN godser-fase1` sidst i `db-migrations.sql`) FØR merge af web/mobil (memory: merge før DDL lægger siden ned). Data-kørsel kun med `--jeg-mener-det` og kun via brugerens shell.
- Persondata: forslagsark og plan-fil indeholder gods-, relations- og medie-id'er og godsnavne, aldrig personnavne (der er 13 levende ejere).
- Commits: Conventional Commits på dansk, ingen Claude-attribution, ingen session-linje.

## Review Focus

1. **Fortryd af en sammenlægning** skal flytte ejerforhold og billeder tilbage og fjerne `sammenlagt_i` — testet i Task 4.
2. **Gammel adresse** `/besiddelse/<sammenlagt id>` og mobilens `/estate/<id>` skal lande på den overlevende række; en kæde (A→B→C) må ikke kunne opstå — Task 2 (vagt) og Task 7/8 (omdirigering).
3. **Anon ser de nye relationer** (`sammenlagt_i`, `hører_under` mellem offentlige godser), og 0 levende lækkes — Task 6 (RLS-test som anon).
4. **Samme ejer på begge rækker** efter sammenlægning bliver to ejerforhold (afgørelse 4A); intet må deduplikeres tavst — Task 4.
5. **Billede flyttet fra majorat til gård** vises på gårdens side og ikke længere på majoratets — Task 5 + Task 7.

### Task 9: Forslagsark og plan-fil

**Files:** Create `tools/godser-471/forslag.py`, `tools/godser-471/README.md`

- `plan.json`-format (operationerne udføres i denne rækkefølge af Task 10):

```json
{ "version": 1, "kilde_db": "<navn>", "kilde_hash": "<md5 over estate+relation som i målingen>",
  "opret":       [{"noegle": "ny:Aalstrup", "navn": "Aalstrup", "slags": "gård"}],
  "saet":        [{"estate": 170, "navn": "Grevskabet Christianssæde", "slags": "grevskab"}],
  "sammenlaeg":  [{"fra": 372, "til": 170}],
  "kopier":      [{"relation": 1234, "til": "ny:Aalstrup", "citat": "Christianssæde med Pederstrup, Aalstrup og Frihedsminde"}],
  "hoerer_under":[{"gaard": "ny:Christianssæde-gård", "majorat": 170, "periode": "1729-1924", "source": 1, "citat": "…"}],
  "flyt":        [{"relation": 5678, "til": "ny:Christianssæde-gård"}] }
```
