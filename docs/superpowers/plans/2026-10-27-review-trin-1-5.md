# Helhedsreview trin 1-5 — plan

> **For agentic workers:** Hovedsessionen orkestrerer; delegerede kald følger spec'ens modelvalg. Steps bruger
> checkbox (`- [ ]`).

**Mål:** Fase 0's fire oversigter leveret og screenet til kontrolpunkt 1; fase 1-3 udføres efter spec'en, når
projektejeren har svaret.

**Arkitektur:** Én ren eksport af repoet (kun sporede filer) er det eneste, reviewerne læser. Hovedsessionen laver
målingerne selv. Tre Sonnet-agenter laver hver sin oversigt i hver sin scratch-mappe. Hovedsessionen screener og
committer.

**Spec:** `docs/superpowers/specs/2026-10-27-review-trin-1-5-design.md`

## Global Constraints

- Læseforbud i hvert brief: `work/`, `work_1939_stamtavle/`, `work_presens/`, `~/.private/`, `*.dump`, `manifest*.json`,
  `kontrolark*`, `token*`, `aktoer*`, `.env*`, `~/.Renviron`; ingen DB-forespørgsler; ingen navne på levende personer.
- Hvert `Agent`-kald sætter `model` eksplicit; ingen Workflow; ingen Fable før fase 2.
- Agenter skriver kun i egen scratch-mappe; kun hovedsessionen committer (`docs/reviews/2026-10-27-trin-1-5/`).
- Stop ved kontrolpunkt 1 og 2.

`SP` = sessionens scratchpad; `EKS=$SP/eksport`; output `$SP/f0/{0b,0c,0d}/`.

## Review Focus

- Eksporten indeholder en ikke-sporet fil med PII → tjek, at `EKS` ikke indeholder nogen `work*`-mappe.
- En funktion defineret flere gange i én fil → målingen bruger den *sidste* definition og tæller gentagelser.
- Overloads (samme navn, forskellige argumenter) → nøglen er navn + argumentliste, ikke kun navn.
- Kronologien mister kilden → hver post skal have fil:linje, og 3 tilfældige stikprøves mod kilden.
- Leverancer citerer personnavne fra prosa → screen før commit.

---

### Task 1: Ren eksport og ledger-udtræk

- [ ] `git archive HEAD | tar -x -C $EKS`. Verificér: `find $EKS -maxdepth 1 -name 'work*'` er tom, og antal filer =
  `git ls-files | wc -l`.
- [ ] Ruling-linjer: `grep -n 'Ruling:'` over `.superpowers/sdd/*/progress.md` → `$EKS/_ledger-rulings.txt` (sti:linje:
  tekst). Verificér antal (60 ved planlægning).

### Task 2 (0a): Målinger → `maalinger.md`

- [ ] Script `$SP/maal/maal.py`, som kører på `EKS`:
  - `funktioner(fil) -> dict[(navn, argsignatur), list[krop]]`: parse `CREATE [OR REPLACE] FUNCTION
    <skema.navn>(<args>) … AS $tag$…$tag$`.
  - Sammenlign sidste krop i `schema.sql` med sidste krop i `db-migrations.sql`, rå og normaliseret (fjern `--`- og
    `/* */`-kommentarer og kollaps whitespace; intet andet). Output: i begge / kun schema / kun migrations / rå
    identiske / normaliseret identiske / divergerende, med liste.
  - Versionssuffiks-filer (`_v[0-9]`, `v[0-9]+`) grupperet efter stamme, med om den ældre refereres (grep i kode, CI,
    skills, runbooks).
  - Død-kandidater: script-filer, hvis basisnavn ikke forekommer andre steder end i filen selv.
  - Tests pr. modul og CI-job; linjer pr. trin (efter systemkortets mappeinddeling, foreløbigt pr. mappe).
- [ ] Verificér stikprøver: 2 divergerende og 1 identisk funktion kontrolleres med øjnene; overload-tilfælde tælles
  korrekt.
- [ ] Skriv `maalinger.md` med metode, tal og lister (lister > 40 rækker samles i et tillæg i samme fil).

### Task 3 (0b, 0c, 0d): Tre Sonnet-agenter parallelt

- [ ] Briefs med: mål, kilder, outputformat og den præcise sti til egen outputmappe, læseforbud, arbejdsmappe = `EKS`,
  »du må ikke ændre noget uden for din outputmappe«, »angiv fil:linje for hver post«, læseloft og en liste over læste
  filer til sidst.
  - 0b `beslutningskronologi.md`: emner og kilder efter spec'en 0b (+ `_ledger-rulings.txt`).
  - 0c `systemkort.md`: pr. trin og forarbejde efter spec'en 0c; åbne issues fra en liste, hovedsessionen lægger i
    `$EKS/_issues.txt` (`gh issue list --state open`).
  - 0d `udestaaende-raa.md`: efter spec'en 0d; kendte punkter fra hukommelsen gives i briefet.
- [ ] Verificér hver: 3 tilfældige poster stikprøves mod kilden (fil:linje passer); ingen personnavne fra prosa
  (grep efter `levende`-personer er ikke mulig — læs leverancen igennem); emnedækning (0b), alle trin (0c).

### Task 4: Screening, commit, kontrolpunkt 1

- [ ] Kopiér de fire leverancer til `docs/reviews/2026-10-27-trin-1-5/`; én commit pr. leverance.
- [ ] Slå Codex-model-id'et for »6.1 terra« op (`codex` CLI/runtime), og notér det til kontrolpunktet.
- [ ] Præsentér for projektejeren: de vigtigste tal og fund pr. oversigt + spørgsmål om fase 1.

### Fase 1-3 (efter kontrolpunkterne)

Spec'en §5 gælder. Briefs til 1a-1e skrives under kontrolpunkt 1. Fase 2 (ét Fable-kald) og fase 3 (rapport)
følger efter kontrolpunkt 2.
