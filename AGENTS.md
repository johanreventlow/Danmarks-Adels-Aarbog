# Agentinstruktioner for genimport- og årbogsarbejde

Disse regler gælder kun arbejde med DAA-import/genimport, source
records/personas, fortolkning, identitetsafstemning, promotion og
importpublicering. De gælder ikke andre produkt-, web-, mobil- eller
formidlingsspor.
Brugerens konkrete instruktioner har altid højere myndighed.

## Bindende styringsgrundlag

Læs først, i denne rækkefølge:

1. `docs/evidensbaseret-genimport/vision.md`
2. `docs/evidensbaseret-genimport/roadmap.md`
3. `docs/evidensbaseret-genimport/teknisk-maalarkitektur.md`
4. `docs/evidensbaseret-genimport/status.md`

Før en plan eller implementering skal opgaven kobles til roadmapmål,
værdikædeled, leverancetype, redaktionel/læserrettet værdi, færdigbevis og det
workflow den erstatter. Omprioritér ikke roadmapet, og opret ikke nye permanente
editionsnavngivne overflader uden en beslutning i `docs/decisions.md`.

Historiske specs, planer, reviews og changelog er
historik, ikke aktuel programstatus. Levende kode og schema er source of truth for tekniske detaljer,
der kan være ændret siden statussnapshotet, og overtrumfer statussnapshotet for
sådanne driftede detaljer.
